# devflow 研发项目全流程交付总控

## 定位
`devflow` 保证"按方法论把系统做出来"；本 skill 保证"做出来的是一个**完整、规范、可验收、可存档的研发项目**"。它定义一个研发项目从立项到结题**应当产出的全套文档**，把每份文档挂到 devflow 管线的对应阶段，并在收尾时做完整性核对。目标：用户从一个需求进来，最后拿到一整套研发项目材料，而不是零散文档。

> 关系：本 skill 是 devflow 的"研发项目交付模式"。文档具体怎么写 → 查 `devflow-report-writing`（各类报告章节模板）与 `devflow-docs`（排版/占位/校验）；需求文档 → `devflow-prd`；技术/架构 → `devflow-architecture`；部署/运维 → `devflow-deployment`。本 skill 只负责"全集清单 + 产出编排 + 完整性核对"。

## 何时使用
- 用户要做一个正式立项的研发项目（科技项目、企业研发、加计扣除、高企、内部研发立项）
- 需要从"提出需求"一路交付到"结项/验收"的全套材料
- 已有系统但缺完整研发项目文档，需要补齐归档
- 用户说"要一整套研发项目文档""完美研发项目""立项到结题"

## 研发项目全周期交付文档全集

按生命周期分八段。每段标注【核心必备】或【按场景可选】，并给出对应产出阶段与模板来源。

### 阶段一 · 立项
1. **立项报告 / 立项申请书**【核心必备】——为什么立项、研发目标与考核指标、研发内容、技术路线、进度安排、经费预算、团队分工、预期成果。模板见 `devflow-report-writing`。
2. **可行性研究报告**【按场景可选，正式科技项目/大额投入需要】——技术可行性、经济可行性、进度可行性、风险可行性、结论。模板见 `devflow-report-writing`。

### 阶段二 · 需求
3. **需求结论纪要**【核心必备】——需求对话产出，来自 `devflow-requirements`。
4. **需求文档 / PRD**【核心必备】——来自 `devflow-prd`：背景、目标、角色、功能清单、流程、非功能需求、验收标准。

### 阶段三 · 计划
5. **项目计划书 / 任务书**【核心必备】——WBS 工作分解、里程碑与进度、资源与分工、质量计划、风险计划、考核指标对齐。模板见 `devflow-report-writing`。

### 阶段四 · 研发实现
6. **产品定义文档**【核心必备】——角色/模块/功能矩阵，来自 `devflow-product-definition`。
7. **架构设计 / 技术方案文档**【核心必备】——来自 `devflow-architecture`（含 ADR）。
8. **研发报告 / 开发报告**【核心必备】——研发内容、关键技术、实现过程、阶段成果，模板见 `devflow-report-writing`。
9. **开发文档 / 二次开发指导**【按场景可选，需移交维护时必备】——代码级事实与开发指引，来自 `devflow-docs`（对应项目事实文件 DEVELOPMENT_GUIDE）。

### 阶段五 · 测试
10. **测试方案 / 测试计划**【按场景可选】——测试范围、方法、用例设计思路、环境、通过标准。
11. **测试报告**【核心必备】——以验收指标为骨架，实测数据支撑，模板见 `devflow-report-writing`；测试执行来自 `devflow-testing`。

### 阶段六 · 试运行
12. **试运行报告**【核心必备（有试运行环节时）】——真实环境运行记录与性能实测，模板见 `devflow-report-writing`。

### 阶段七 · 验收 / 结题
13. **验收报告 / 验收申请**【按场景可选，需正式验收时必备】——对照考核指标逐项验收结论、验收组意见。模板见 `devflow-report-writing`。
14. **结题报告 / 结项报告**【核心必备】——项目全周期总结，最完整，模板见 `devflow-report-writing`。
15. **经费决算报告**【按场景可选，有经费管理时】——预算 vs 实际执行。

### 阶段八 · 交付使用
16. **用户操作手册**【核心必备】——面向最终用户，模板见 `devflow-report-writing`。
17. **部署 / 运维手册**【核心必备】——来自 `devflow-deployment` + `devflow-docs`。
18. **交接文档**【按场景可选，移交他人维护时必备】——账号/环境/密钥位置、已知问题、待办、联系人。

### 附件材料【按场景可选】
19. 知识产权证明（软著 / 专利 / 商标）
20. 科技查新报告（正式科技项目验收常需）
21. 系统截图清单、测试用例汇总、参考文献（通常并入结题报告附录）

> **最小完整集（用户常说的"通通都搞出来"）**：立项报告 → 需求文档(PRD) → 项目计划书 → 研发报告 → 测试报告 → 试运行报告 → 结题/结项报告 → 用户操作手册 → 部署运维手册。其余按项目性质（科技项目/加计扣除/内部研发）增补。

## 执行步骤（从需求到完美研发项目）
1. **判定项目性质**：是科技计划项目 / 研发费用加计扣除 / 高企 / 企业内部研发立项 / 普通交付？据此确定"全集"里哪些【按场景可选】项必须做（如加计扣除重立项+研发报告+经费；科技验收重可行性+查新+验收报告）。
2. **先对话**：走 `devflow-requirements`，把模糊需求收敛成需求结论纪要（黄金法则，不可跳过）。
3. **列出文档产出计划**：对照本全集列出本项目要产出的文档清单与顺序，缺失信息用 XXX 占位待补。
4. **按 devflow 管线推进**：PRD → 产品定义 → 架构 → …… → 测试 → 部署，每阶段顺手产出对应文档（不要等到最后补，边做边落盘，保证文档与代码一致）。
5. **收尾成套产出报告**：用 `devflow-report-writing` 的模板逐份产出研发报告、测试报告、试运行报告、结题报告、用户手册等，全部走 `docx` skill，排版统一。
6. **完整性核对**：用下方自检表逐项打勾，缺项补齐或标 XXX，确保"完整研发项目"。
7. **归档**：全套文档输出到 outputs，命名规范统一（项目名_文档类型_版本），用 file:// 分享清单。

## 完整性自检表（交付前逐项核对）
- [ ] 立项报告（目标/考核指标/技术路线/预算/团队齐全）
- [ ] 需求结论纪要 + PRD（验收标准可量化）
- [ ] 项目计划书（WBS/里程碑/考核指标对齐）
- [ ] 架构设计文档（分层/目录/ADR）
- [ ] 研发报告（关键技术展开到子模块级，与代码一致）
- [ ] 测试报告（以指标为骨架，实测数据支撑，达标判定）
- [ ] 试运行报告（环境写实，性能实测表）
- [ ] 结题/结项报告（全周期总结，效益带数据）
- [ ] 用户操作手册（步骤化，配图，FAQ）
- [ ] 部署/运维手册（可复现部署）
- [ ] 按场景可选项已按需补齐（可行性/验收/经费/知产/查新）
- [ ] 全套命名口径统一、版本号规范、排版规范一致
- [ ] 所有结论有数据/代码事实支撑，未实测处标 XXX

## 交接
- 上游：devflow（管线）、devflow-requirements（需求）。
- 文档模板：devflow-report-writing（各报告章节）、devflow-docs（排版/占位/校验）、devflow-prd / architecture / deployment / testing（对应专业文档）。
- 落地：docx skill 生成，输出 outputs。

## 关键陷阱
- 只交系统不交全套文档 → 不算"完整研发项目"，按全集核对。
- 文档最后补、与代码脱节 → 边做边落盘，报告写前用代码证据核对。
- 不分项目性质一刀切 → 先判定性质，确定可选项取舍（加计扣除/科技验收侧重不同）。
- 考核指标不贯穿 → 立项定的指标要在测试报告、验收报告、结题报告里逐项回收闭环。
- 结论无数值支撑、编造数据 → 用实测，未测标 XXX。
- 命名/版本/口径不统一 → 全套统一规范。

## 验证
- 完整性自检表全部通过（核心必备项无一缺失，可选项按项目性质补齐）。
- 考核指标从立项 → 测试 → 验收 → 结题全链路闭环。
- 每份文档章节匹配 devflow-report-writing 模板，排版规范一致，docx 校验通过。
- 全套文档命名规范、口径统一、结论有据。
