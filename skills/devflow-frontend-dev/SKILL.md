# devflow 前端开发

## 定位
把原型和设计风格落地为可运行的界面。前端严格遵循分层架构：页面/组件只负责渲染与交互，通过 API 与后端通信，绝不直接访问数据库或写业务重逻辑。视觉严格引用设计 token，不自造样式。

## 何时使用
- 实现或修改任意页面/组件
- 做数据展示与可视化
- 前后端联调

## 产出物
页面、组件、状态与数据获取逻辑，通过构建、lint，契约与后端对齐。

## 执行步骤

### 1. 遵循架构与目录
- 按 devflow-architecture 的分层放置文件：页面、可复用组件、状态、API 调用、工具各归其位。
- 区分服务端渲染与客户端交互组件（按所用框架约定），交互组件才加客户端标记。
- 页面不写业务重逻辑，复杂逻辑下沉到 hooks/service/lib。

### 2. 样式（对齐 devflow-design-style）
- 严格引用设计 token（色彩/间距/圆角/字体/图标），禁止硬编码色值和自造样式。
- 统一样式方案（工具类 / CSS-in-JS / CSS 模块，按技术栈），不混用多套。
- 图标统一一个库，删除未使用的 import。
- 覆盖组件全部交互态（默认/hover/active/disabled/focus）。

### 3. 数据获取与状态
- 通过 API 层取数，统一处理 loading / empty / error / success 四态。
- 局部状态用组件状态；跨组件共享用状态管理方案（按技术栈选轻量的）。
- 请求错误按后端统一错误契约处理，给用户友好反馈。
- 异步循环遵循代码约定：顺序 await 用 for...of，独立并发用 Promise.all，禁止 forEach+async。

### 4. 常见页面样板（按类型）
- **列表/表格页**：筛选 + 分页 + 排序 + 空态 + 行操作。
- **详情页**：信息分区 + 关联数据 + 操作区 + 状态展示。
- **表单页**：字段校验（前端校验 + 后端校验兜底）+ 提交态 + 错误提示 + 成功反馈。
- **看板/仪表盘**：概览卡片 + 数据可视化（按 token 手写或用既定图表方案）+ 关键指标。
- **流程/审批页**：当前状态 + 可执行动作（按权限显隐）+ 历史留痕时间线。
- 涉及富文本/Markdown 渲染时，做好转义与安全处理，防 XSS。

### 5. 响应式与可访问性
- 按设计规范的断点适配移动/桌面。
- 语义化标签、可聚焦、对比度达标、alt/aria 齐备。

### 6. 自检
- 删净未使用的 state/import/变量。
- 构建 + lint 通过；四态齐全；无控制台报错；交互闭环。

## 交接
- → devflow-backend-dev：调用的 API 契约需对齐。
- → devflow-testing：前端交互路径是冒烟脚本来源。
- 上游依赖 devflow-prototype / devflow-design-style / devflow-code-conventions / devflow-tech-stack。

## 关键陷阱
- 硬编码样式、自造色值 → 视觉割裂，改主题时全局返工。
- 页面直连数据库/塞满业务逻辑 → 破坏分层、难测、泄露。
- 只做成功态，漏 loading/empty/error → 体验残缺。
- 前端校验但无后端兜底 → 可被绕过，脏数据入库。
- 未清理 import/state → lint 报错、体积虚高。
- 凭记忆写框架 API → 先读当前版本文档。

## 验证
- 构建/lint 通过，页面可访问，无控制台错误。
- 视觉与设计 token 一致；四态齐全；交互闭环（触发→反馈→结果）。
- 响应式与可访问性达标。
