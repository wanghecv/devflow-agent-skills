# devflow 测试与冒烟

## 定位
测试验证三件事：功能对不对、非功能指标达不达标、上线稳不稳。测试点直接来自 PRD 验收标准、产品定义的权限矩阵/状态机、以及架构的关键能力。本 skill 提供通用测试方法论，具体指标由项目 PRD 决定。

## 何时使用
- 功能开发完成需验证
- 交付前编写测试报告
- 部署前跑冒烟
- 验证性能/鲁棒性/安全等非功能指标

## 产出物
分层测试用例、冒烟测试清单、《测试报告》。

## 执行步骤

### 1. 分层测试策略（测试金字塔）
- **单元层**：核心业务逻辑、状态机（合法/非法流转）、权限判定、计算/聚合函数、工具函数。覆盖边界与异常分支。
- **集成/API 层**：每个接口测正常(200)/未认证(401)/越权(403)/非法输入(400)/不存在(404)；跨多步写操作测事务原子性（中途失败应回滚、无脏数据）。
- **数据层**：约束生效、留痕 append-only（每次操作恰好一条、历史不可改）、关联完整性。
- **端到端/UI 层**：关键用户旅程走通（登录→核心操作→结果），覆盖 loading/empty/error/无权限四态。
- 优先级：核心业务路径与安全/权限必测，边缘 UI 可抽样。

### 2. 冒烟测试（部署后必跑的最小集）
1. 应用可访问、健康检查通过。
2. 用管理员/普通账号登录成功（认证链路通）。
3. 核心业务主流程走一遍，数据正确落库、状态推进、有留痕。
4. 越权访问受限资源被正确拒绝(403)。
5. 关键页面/接口无致命错误，日志无异常。
> 冒烟只验"活没活、主路通不通"，不追求全覆盖，快速放行。

### 3. 非功能指标验证（按 PRD 定义）
对 PRD 中每条量化指标，定义验证方法：
- **性能（如响应时间/吞吐）**：对目标接口/操作做足够多次请求，记录 P50/P95/P99 与最大值，判定是否达标。样本要足够，避免均值失真。
- **鲁棒性（如并发/长期运行/大数据量）**：构造并发与批量数据，验证无数据竞争（事务/锁保证）、隔离正确、长周期累积后仍准确、资源（内存/连接）不异常增长。
- **效率/业务收益类指标**：先定义度量口径与基线，对比上线前后，计算提升幅度。缺基线数据用 XXX 占位并给出采集方法与计算公式。
- **安全**：注入、越权、XSS/CSRF、敏感信息泄露等常见项。

### 4. 测试报告结构
封面/概述 → 测试环境（版本、部署方式）→ 测试范围与方法 → 分项结果（每项含用例、步骤、预期、实测、结论；表格化）→ 缺陷与修复 → 非功能指标实测与判定 → 结论（是否达标/可上线）。未知信息用 XXX 占位。

### 5. 缺陷管理
- 记录缺陷：复现步骤、预期 vs 实际、严重级别、修复状态。
- 回归验证：修复后重测并跑相关冒烟，防回归。

## 交接
- → devflow-deployment：冒烟通过是部署放行前置。
- → devflow-docs：测试结论汇入测试报告/验收文档。
- 上游依赖 backend-dev / frontend-dev / database 的实现与 PRD 验收标准。

## 关键陷阱
- 只测正常流不测越权/非法输入/非法流转 → 安全与一致性漏洞漏网。
- 不验事务回滚 → 并发下数据不一致。
- 性能样本太少 → 指标失真，用足够次数取 P95/P99。
- 效率指标无基线口径 → 提升无法证明，先定义度量口径。
- 修复不回归 → 改一个坏一个。

## 验证
- 全部冒烟步骤通过。
- PRD 每条量化指标有实测数据/计算方法与明确结论。
- 核心业务路径、权限、事务、留痕均被测试覆盖；缺陷已闭环。
