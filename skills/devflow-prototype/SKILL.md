# devflow 原型设计

## 定位
在写代码前，用低保真原型把"每页放什么、信息怎么排、用户怎么操作、系统怎么反馈"想清楚。原型是最便宜的试错——改一根线框比改一屏代码快得多。本阶段产出的是结构和交互蓝图，不追求视觉精美（视觉留给设计风格阶段）。

## 何时使用
- 页面清单确定后要设计布局与交互
- 复杂流程需要先验证交互路径
- 开发前需要与需求方对齐界面预期

## 产出物
各页面的线框描述（布局结构 + 信息层级 + 交互流 + 状态），可用文字、ASCII 线框、或 HTML/图片原型表达。

## 执行步骤

### 1. 逐页拆解（对每个页面）
- **页面目标**：用户来这页要完成什么。
- **信息架构**：需要展示哪些信息，主次层级如何，哪些折叠/分页/懒加载。
- **布局结构**：区域划分（导航/头部/主区/侧栏/底部），关键组件位置。
- **交互流**：用户操作 → 系统响应 → 下一步，逐步骤描述。
- **状态覆盖**：空态、加载态、错误态、无权限态、边界（超长文本/大量数据）。

### 2. 关键流程串联
- 把跨页面的核心流程（如登录→创建→审批→完成）画成流程图，标注每步所在页面和跳转。
- 验证流程闭环，无死路、无断点。

### 3. 低保真原则
- 用灰阶/占位块表达，不纠结配色和像素。
- 重点是结构与交互对不对，不是好不好看。
- 快速产出、快速评审、快速改。

### 4. 表达形式（按条件选）
- 文字 + ASCII 线框：最快，适合与 AI/工程师沟通结构。
- HTML 静态原型：可点击，适合验证交互流。
- 图片/工具线框：适合给非技术需求方看。

### 5. 评审与迭代
- 拿原型对照 PRD 核心场景逐一走查，确认每条需求都有对应界面承载。
- 收集反馈，迭代到需求方确认，再进入开发。

## 交接
- → devflow-design-style：原型确定结构后，设计阶段赋予视觉语言。
- → devflow-frontend-dev：原型是页面实现的直接蓝图。
- 上游依赖 devflow-product-definition 的页面清单。

## 关键陷阱
- 过早追求高保真视觉 → 改起来慢，偏离"快速试错"初衷。
- 漏画空态/加载态/错误态/无权限态 → 开发时抓瞎，体验残缺。
- 只做单页不做流程串联 → 页面间跳转断链。
- 原型与 PRD 场景不对齐 → 有需求没界面承载。

## 验证
- 每个页面都覆盖布局/信息层级/交互流/四种状态。
- 核心跨页流程闭环无断点。
- 原型走查覆盖 PRD 全部核心场景，需求方已确认。
